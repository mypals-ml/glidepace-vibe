## Implementation Details

- Updated the task details Start Date control so "Reset to Auto" is not disabled when the persisted Start Date is empty.
- Updated `applyOptimisticTaskDateUpdate` so a reset-to-auto action clears the persisted `startDate` but immediately derives a `tempStartDate` for the edited task.
- The derived temporary start date follows the existing display rules:
  - If a target date exists, derive the start date backward from target date, estimate, and estimate unit.
  - If the estimate is missing, use the same default duration convention as task mapping: 8 for hours, 1 otherwise.
  - If there is no target date, fall back to today's date.
- Kept target date unchanged during reset so the Gantt task bar can immediately remain positioned from the auto start date and existing target.
- Updated feature documentation to describe that Reset to Auto remains available for auto-dated tasks and updates the details/Gantt display immediately.
